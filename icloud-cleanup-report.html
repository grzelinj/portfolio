iCloud cleanup report — sample run

iCloud Cleanup · local tool for safely finding duplicate photos and videos

Scope: a real run against my own iCloud Photos library

These are real numbers and entries from running the tool on my own photo library. The filenames below are the default, generic names iPhone/iCloud assigns automatically (IMG_XXXX) — they carry no personal data or content description, so they're shown as-is, unredacted. The actual photos and videos are never shown here or processed anywhere off my own disk.

🔍 Scan and duplicate detection

Scanned the full Pictures\iCloud Photos\Photos library: 22,106 files, 145.7 GB. The tool groups photos taken a few seconds apart (the same burst/scene) and flags candidates for review — it found 1,103 series, 2,121 candidate photos in total (assuming one is kept per series), ~4.5 GB potentially recoverable.

🎬 Video sorting

A separate pass for video: 3,058 videos analyzed (skipping 853 cloud-only placeholders not yet downloaded), ~75.6 GB, sorted by year and type — e.g. screen recordings kept separate from camera footage, so it's easier to judge what's actually worth keeping.

🧯 Safety — quarantine, not deletion

No file is ever deleted directly. Candidates are moved to a quarantine folder with a full manifest (original path + destination path + move timestamp) — the actual deletion decision is made manually, only after reviewing the list. No file has ever been deleted without that step.

⚙️ Adaptive tuning against Apple's throttling

While forcing the whole library to download (rehydrate) from the cloud to disk, I hit mild throttling on Apple's side after ~2h of continuous downloading — throughput dropped from ~23 to ~14 files/min, and errors started appearing on file types that had been fine before. The fix: dropping from 6 to 4 parallel threads and logging progress at the single-file level — the earlier version, which only logged every 200 files, went silent for 2 hours with no error trace at all when it got stuck on one cloud placeholder file.

A private tool that runs locally on my own machine — no repo or hosted demo, since it operates on a real photo library. This report shows real data from an actual run (counts, generic filenames, timestamps) — no photos/videos themselves and nothing that identifies a person.
